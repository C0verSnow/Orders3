# issue #49：按最新持仓维护平仓单，历史失败不再挡住整轮

## 用户确认的行为

平仓数量以 Gate `/futures/usdt/positions` 的本轮持仓为准，取相反数。SOL 分笔入仓 0.9 和 0.1 是两条真实成交事件，不是两张待发布的平仓单；即使七天历史合计为 1 张，当前持仓为 19 张，平仓单仍为 -19 张。多空双向持仓分别维护。

用户在本次会话明确确认：历史同步出错，也继续按最新持仓维护平仓单；未知交易、创建前复核等保护继续保留，无法确定目标价的持仓暂停调整。

## 执行顺序和失败处理

```text
十分钟持仓维护
  尝试完整读取七天成交并提交历史、固定保证金
    历史接口、分页或成交字段错误 → 保留旧历史与水位，记录错误
    数据库错误、持仓接口错误或持仓校验失败 → 停止本轮，不交易
  读取并保存最新持仓，原样返回给平仓计算
  按持仓张数与均价、固定保证金计算目标
    历史成功 → 沿用最新入仓固定值/首次持仓观察规则
    历史失败 → 只读取已有固定值，不初始化、不覆盖
    缺少固定值 → 该持仓返回 failed，保留旧单，其余持仓继续
  核对实时追踪单，保留/停止/创建只减仓单
    每次创建前再次读取持仓数量和均价、有效同方向单
  历史未恢复 → 整轮记录 failed，保留平仓部分的真实执行结果
```

历史失败时可使用当前 API Key 摘要、合约、方向下已保存的固定保证金，包括历史成交固定值和此前已确认的旧持仓首次观察值。不会拿当前浮动保证金当作新的固定值，不借用其他账户或方向的数据。没有固定值的持仓保留既有平仓单，不停止或补建该方向订单。历史恢复后再按真实新入仓/加仓更新固定值。

这个降级方案使用的是上次确认的固定值。历史暂不可用期间，程序无法确认是否有遗漏的新入仓/加仓，因此该值可能晚于市场变化才更新；界面与持久化任务继续显示历史失败，不会宣称整轮成功。只减仓属性限制增仓风险，但不保证目标收益、成交时间或成交价格。

正常路径保留整批价格/数量校验后再写入、已激活单保留、策略字段不全不补单、结果未知不重试、持仓变化不创建、维护授权和串行锁。开仓流程和人工解除未知交易仍要求完整历史同步成功；本次降级只用于平仓维护。

## position 不一定是整数

[Gate 官方数量字段迁移公告](https://www.gate.com/announcements/article/48788)同样列出了 position 的 `size`：没有 `X-Gate-Size-Decimal: 1` 时可能向零截断。原实现虽用 position 定数量，但再次读取的快照与页面同步不相同，而且持仓请求未启用准确响应。

现在每次持仓请求都携带小数响应头，再校验整数范围。当前项目的 SQLite 持仓和追踪单发布仍按整数张数运行；真实 size 为 0.9、-0.9、1.9、-1.9 时明确报“持仓 size 必须为有效整数张数”，停止本轮，绝不截断、四舍五入或假装空仓。不是本次支持小数持仓交易。

历史继续精确处理小数，错误文案拆分成“size 不能为零”和“size 与 close_size 方向冲突”，不会再把零值误说成方向冲突。
