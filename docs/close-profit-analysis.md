# Issue #12：平多仓净利润怎么算

核查日期：2026-10-14。需求见 [issue #12](https://github.com/C0verSnow/Orders3/issues/12)。本次交付公式分析和示例，不修改自动交易代码。

## 先说结论

“投入 1 USDT，净赚 3 USDT，本金加净利润共 4 USDT，ROI 为 300%”这个算术关系成立。若本金加利润一共只有 3 USDT，净利润就是 2 USDT，ROI 为 200%。

当前程序不能可靠地实现前一种目标。问题不在于必须把公式里的 3.1 改成 4，而在于：计算漏了合约乘数，使用的是当前持仓保证金而非固定开仓成本，没有逐笔扣除实际费用，而且计算结果只是追踪单激活价。

本文把“开仓成本”先解释为开仓时确定的保证金投入 M0，手续费另计；如果你的 1 USDT 已包含开仓手续费，必须把 ROI 分母和本金口径一起改成这笔总投入，不能混用。

## 本金、价值、利润分别是什么

| 名称 | 含义 |
| --- | --- |
| M0：开仓保证金投入 | 开仓时确定的投入，本文 ROI 的固定分母，不是合约全部价值 |
| N：开仓名义价值 | 实际币数量 × 开仓均价，杠杆交易中通常大于保证金 |
| 释放的保证金 | 平仓后不再占用的抵押资金；全仓模式共享账户保证金，不能理解成交易所每笔必定打回固定 1 USDT |
| 毛利润 | 价格变动带来的盈亏，尚未扣费 |
| 净利润 | 毛利润扣除开平仓手续费、净支付资金费和其他可归属成本 |
| 本金加净利润 | 以投入 M0 为基准归属到这笔交易的最终资金 M0 + 净利润，不是平仓成交额 |
| ROI | 净利润 ÷ M0 × 100%，这是本需求口径，可能与交易所页面使用当前保证金的收益率不同 |

保证金只是抵押资金，不会在计算价格差利润时再扣一遍。手续费只扣一次；如果已经使用包含费用的 realised_pnl，就不能再重复扣除相同费用。

## 程序现在实际做了什么

代码入口在 [fetcher.cpp](../src/services/fetcher.cpp) 的 closePositionOrders，计算在 [decimal.hpp](../src/core/decimal.hpp) 的 closePrice。对多仓设：n = size > 0，E = entry_price，M = 本次读取的 initial_margin。

```text
本地 value = n × E
激活价格 A = E × (1 + 3.1 × M / value) × 1.01
           = 1.01 × (E + 3.1 × M / n)
```

程序采用精确十进制计算，再按 mark_price 文本的小数位数四舍六入五成双。之后发送 amount = -size、activation_price = A、price_type = 3（标记价格）、price_offset = 1% 的 reduce_only 追踪单。

这里的 value 是程序自行定义的量，不能当作真实 USDT 开仓价值：Gate 的 size 是合约张数，每张对应多少币还要乘 quanto_multiplier。当前流程没有读取这个乘数。正式价格步长也应读取合约元数据，不能仅凭 mark_price 文本的小数位数判断。

## 用交易所的盈亏公式检验现行公式

设 c 为每张合约的币数量，q = n × c 为实际币数量，P 为最终平均成交价。USDT 线性合约多仓：

```text
毛利润 G = q × (P - E)
```

即使先作最有利的简化，假定恰好按激活价 A 成交且不扣费用，把现行 A 代进去，也得到：

```text
G = n × c × (A - E)
  = 0.01 × (n × c × E) + 3.131 × c × M
  = 0.01 × N + 3.131 × c × M
```

这是对代码和官方盈亏定义的代数推导。它并不等于 3 × M0；M 与 M0 也不一定相同。即使 c = 1、M = M0，结果仍是 1% 的名义价值加 3.131 倍保证金，尚未扣费。3.1 是价格目标系数，并不是“本金和利润合计 3.1 倍”。

另外，Gate 官方说明全仓 initial_margin 会随市场变化，当前程序每轮重新读取它。拿它当固定开仓投入，会让目标跟着市场变化。同一合约同方向的多次开仓在当前代码里按一条持仓处理，也没有逐笔开仓成本、逐笔费用分摊，因此目前只能算持仓整体目标，不能兑现每笔原始订单独立 300% 的口径。

## 符合需求的净利润和目标成交价

令 Fo 为开仓手续费，Fc 为平仓手续费，U 为净支付资金费（收到资金费时为负），H 为其他归属成本。以下目标必须使用同一笔交易、同一数量范围的数据。

```text
净利润 π = q × (P - E) - Fo - Fc - U - H
目标 π = 3 × M0
ROI = π / M0 × 100% = 300%
本金加净利润 = M0 + π = 4 × M0
```

如果费用总额 F = Fo + Fc + U + H 已确定：

```text
目标成交价 P* = E + (3 × M0 + F) / q
             = E × [1 + (3 × M0 + F) / N]
```

如果开平仓费率分别为 ro、rc，且 Fo = q × E × ro、Fc = q × P × rc，则要把随成交价变化的平仓费一起解进去：

```text
P* = [q × E × (1 + ro) + 3 × M0 + U + H] / [q × (1 - rc)]
```

这里 q > 0、M0 > 0、rc < 1。已经计入平均实际成交价的滑点不要再当同一笔 H 重复扣除。未来费用尚不确定时只能估计目标，实际净利润仍要按真实成交和流水结算。若成本口径为“含开仓费的总投入 C”，则统一改为 π = 3C、ROI = π/C、最终资金 C+π，并核对该笔开仓费在现金流中只计一次。

## 完整数值示例：投入 1，净赚 3

以下是演算假设，不是当前某个合约的真实行情、费率或保证金要求：

| 参数 | 假设值 |
| --- | --- |
| 开仓保证金 M0 | 1 USDT |
| 开仓均价 E | 100 USDT/币 |
| 合约张数 n | 100 张 |
| 每张币数量 c | 0.001 币/张 |
| 实际币数量 q | 0.1 币 |
| 开仓名义价值 N | 10 USDT |
| 开仓费率 ro、平仓费率 rc | 各 0.05%，即 0.0005 |
| 资金费 U、其他成本 H | 都为 0 |

代入含费公式：

```text
P* = [0.1 × 100 × 1.0005 + 3 × 1] / [0.1 × 0.9995]
   = 13.005 / 0.09995
   ≈ 130.115057528764 USDT/币

毛利润 ≈ 0.1 × (130.115057528764 - 100)
       ≈ 3.011505752876 USDT
开仓手续费 = 0.1 × 100 × 0.0005 = 0.005 USDT
平仓手续费 ≈ 0.1 × 130.115057528764 × 0.0005
           ≈ 0.006505752876 USDT
净利润 ≈ 3.011505752876 - 0.005 - 0.006505752876 = 3 USDT
ROI = 3 / 1 × 100% = 300%
本金加净利润 = 1 + 3 = 4 USDT
```

1 USDT 保证金和 0.005 USDT 开仓费在此分开列账，需要另有费用余额。若总预算连手续费只有 1 USDT，需重新确定保证金和数量，不能直接套用本表。暂不计任何费用时，同样数量的目标成交价是 130 USDT/币。

再用同一组持仓参数检验当前程序，额外假设本次 initial_margin 也恰好为 1：

```text
本地 value = 100 × 100 = 10000
当前激活价 A = 100 × (1 + 3.1 / 10000) × 1.01 = 101.03131
```

若假设按这个未舍入激活价成交，毛利润只有 0.103131 USDT；开仓费 0.005，平仓费 0.0050515655，净利润为 0.0930794345 USDT，ROI 约 9.30794345%。本金加净利润约 1.0930794345 USDT，远小于目标 4 USDT。这个对比直接展示了漏掉合约乘数的影响；真实追踪成交还会与激活价不同。

## 追踪单的 1% 为什么不能保证收益

当前 A 只在标记价格达到阈值时激活追踪，之后按 1% 回撤规则触发平仓。它不代表马上按 A 成交。即使理想化地设最高跟踪价恰好为 A、回撤成交价为 0.99A，要以 P* 为理想成交目标也应估算 A = P*/0.99，而非简单乘 1.01；1.01 × 0.99 = 0.9999。实际标记价与成交价差、回撤期间变化和滑点仍会影响结果。

因此不能只把 3.1 改成 3 或 4，也不能只补一个 1% 系数就宣称保证净赚三倍。若后续要实现该策略，需要先确定开仓成本是否含费、按逐笔订单还是合并持仓计算、继续追踪还是采用其他平仓方式，再增加固定成本记录、合约乘数和价格步长、费用流水及数量分摊。本次没有修改策略或发出真实交易请求。
