# 预测消失后清理旧开仓单（price #18）

关联 [price#18](https://github.com/f1515x/price/issues/18) 和 [Orders3 PR #55](https://github.com/C0verSnow/Orders3/pull/55)。用户已确认修复实际运行的 Orders3，并要求预测成功刷新后立即清理旧开仓单，新单保持原开仓时间。

## 现场证据与原因

SSH 只读检查 `192.168.1.245`，容器 `orders-dashboard` 健康，镜像源码为 `7bd50c44259626fc9fd6b4a465aa01f6d8318afa`。`/api/data` 返回只有时间戳的来源记录和空预测列表，抓取无错误；`/api/orders` 仍有 SPX500_USDT 状态 1、`reduce_only=false` 的订单 1212571。另一个 SNDK_USDT 订单 1204103 是只减仓保护单，应保留。

来源计划为 13:00，开仓计划为 14:00。原 `Dashboard.refreshSources()` 只保存快照，清理仅在独立开仓流程发生；`openOrders()` 又在自动执行且来源为空时提前报错，未进入已有撤单逻辑。不是容器宕机，也不是页面单独残留旧数据。

## 当前行为

1. 完整抓取并保存预测；抓取、分页或数据校验失败不清理。
2. 预留已有 Gate 任务槽，等待当前 Gate 任务完成；来源清理与开仓、持仓维护和订单同步串行，配置租约覆盖整个流程。
3. 复用 `openOrders()` 的整批精度校验、实时 Gate 分页、逐笔参数匹配和撤单意图。按合约、有符号数量、对齐激活价匹配；每条旧单最多匹配一次。参数变更或多余重复单也按既有失配规则清理，替代单留到开仓计划。
4. `source-cleanup` 模式只停止未匹配的状态 1 开仓单；保留状态 2、所有只减仓保护单及匹配成功的订单。空数组和只有时间戳都清理；不读取创建所需的成交历史，不创建任何新单。
5. 来源刷新后的清理不依赖自动开仓开关，覆盖手动、定时、启动抓取与 `--fetch-only`。独立自动开仓遇到空预测也进入清理，不再提前退出。新开仓时间、七天入仓限制与平仓维护规则沿用原实现。
6. 撤单确认后立即保存状态 5；中途失败保留已成功结果。已保存预测但清理失败时明确报告“预测已更新，但旧开仓单清理失败”。未知结果继续使用原意图阻断，不自动重发。

此改动需要 Gate 凭证和撤单权限，成功撤单无法通过回滚代码恢复。每分钟快照同步及 `--list` 仍只读。合并前不替换生产容器，不手动撤销真实订单；PR 等待用户 review。

这是熟悉的既有匹配与撤单流程修复，没有新增依赖或工具。已通过 GitHub 读取原 issue、PR 和 CI；未检索或借鉴外部同类开源项目，没有复制第三方代码。
