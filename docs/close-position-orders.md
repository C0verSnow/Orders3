# 每 10 分钟维护自动平仓追踪单

Issue #43 恢复历史分支 `feature-issue-21-fixed-margin` 的平仓策略。用户已明确确认：已激活旧单保留，并阻止同合约同方向补单。此规则替代之前“自动保护单功能已取消”的说明。

独立任务每 10 分钟执行一次，不受来源抓取 Cron、自动开仓开关或来源订单是否为空控制。每分钟及手动刷新仍只读取持仓和订单。任务串行执行：完整同步最近七天真实成交及保证金观察值 → 同步持仓 → 读取实时持仓、合约规则和全部追踪订单 → 保留、停止或创建平仓单。接口失败记录失败原因，在后续周期重试；忙时等待下次调度检查，不叠加交易。重启不补跑旧批次。

平仓使用只减仓跟踪单：数量为当前持仓张数的相反数，`reduce_only=true`；负数量用 `is_gte=true`，正数量用 `false`。固定 `price_type=3`（标记价）、`price_offset="1%"`、`pos_margin_mode="cross"`、`position_mode="dual_plus"`。不依赖 Supabase 的开仓步长。

以 E 为真实持仓均价，s 为有方向的整数张数，q 为 Gate 合约乘数，M 为固定保证金观察值：

```text
原始目标 = E + 3.1 × M ÷ (s × q)
多仓激活价 = 原始目标 × 1.01
空仓激活价 = 原始目标 × 0.99
最终激活价按 Gate order_price_round 对齐，中点取偶数倍。
```

例如 E=100、张数=2、q=0.1、M=1、步长=0.5 时，多仓激活价=116.5；空仓张数=-2 时为83.5。此价格是追踪激活价，不是成交限价。3.1 倍是费用前的目标系数，近似补偿不保证回撤后的成交收益，也未扣手续费、资金费或滑点。

保证金优先取当前账户、合约、方向的最新真实成交对应的固定观察值。已存在持仓但七天内没有可见入仓成交时，可保存首次真实持仓保证金观察值，绝不捏造入仓事件或入仓时间。新入仓、加仓成交替换固定观察值；单纯行情、杠杆、保证金或减仓变化不覆盖已确定值。页面持仓字段仍显示交易所本轮实时保证金，历史表和平仓计算使用固定值。

维护规则：

- 从 Gate 实时分页列表匹配同合约、同方向、数量、激活价和完整策略参数；已有符合策略的未激活单保留，重复轮询及重启不重复创建。
- 已激活（状态2）的同方向单保留，无论数量、价格是否变化，本轮不停止、不补同方向新单。
- 无已激活单时，保留一张匹配的状态1单；停止其余同方向状态1单，缺少匹配单时再补建。加减仓改变均价或数量后按新持仓重算；减仓不重置固定保证金。
- 交易所已有订单缺少完整策略字段时保留，并返回待人工核对的错误，不凭猜测创建重复单。没有对应有效持仓的旧订单保持原样。
- 整批价格、数量、停止订单 ID 先校验；每次停止前再次核实旧单仍未激活，每次创建前重新确认持仓数量、均价和同方向有效订单。变化则停止本轮，交给下一周期重新同步。
- 只允许已领取的维护任务授权交易；与其他 Gate 任务共享互斥和凭证租约。写入前保存交易意图与请求身份。超时、异常响应或缺少订单 ID 均保持待核对状态，后续轮询及重启禁止自动重发。

`GET /api/orders` 的 `close_execution` 返回本轮真实 `created/stopped/skipped/failed`，错误同时通过 `error`、运行事件和持久化任务记录反映。没有进行过维护时为空数组。维护写入会对真实账户生效；日常手动刷新只读。

接口定义：[Gate 官方期货 API](https://www.gate.com/docs/developers/apiv4/en/futures/#get-trail-order-list)。
