# 表格分页交互回退与冗余检查

用户要求恢复左右翻页按钮上一次的点击交互，并检查仓库里的明确问题及无用代码。此改动在独立分支 `feature/table-pagination-cleanup` 和 [PR #56](https://github.com/C0verSnow/Orders3/pull/56)，不包含 [订单修复 PR #55](https://github.com/C0verSnow/Orders3/pull/55)。

## 原因与修改

Git 历史 `63e184a` 之前，共享 Button 未传入 status 的点击不自动显示请求反馈；随后增加自动 loading/success，而表格控件没有显式关闭，所以分页后箭头会变成加载图标和成功勾。翻页本身是本地表格状态更新，当前页面并没有在等待请求。

上一页、下一页、排序、查看详情及详情的两个关闭按钮显式使用已有 `status="idle"`，保留原来的悬停、按压、焦点和表格行过渡。按钮保持原图标/文字，支持连续点击及键盘切页；首尾页禁用规则保留。异步保存和刷新继续使用现有状态反馈；不修改共享 Button 的行为。

## 冗余检查

对 apps、packages、scripts、desktop 入口及引用进行了静态扫描，并阅读了主要 API、配置、开平仓、持仓和调度路径。

- 删除未被导入或调用的 `Select` 组件及其专用类型导入。全仓库 `Select` 只有这处组件定义及文档/CI 步骤同名文本，实际表单使用分段选择和输入组件。
- 删除表格 `useMemo(() => rows, [rows])`，直接把同一 rows 引用传给 TanStack Table；表格条目计算所需的 useMemo 保留。
- 未发现其他能确认无用的业务导出。部分函数只有一个生产调用但也被测试引用；历史归档、兼容脚本、生成资源源头和构建/发布入口各有用途，未删除。
- 静态检查不等于证明仓库没有其他 bug；没有以推测为由修改交易、权限、锁或增加依赖。

这是已有组件局部回退，已通过 GitHub 对照本仓库历史和 CI；没有检索或借鉴外部同类项目，没有引入新工具。
