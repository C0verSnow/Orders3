# 入仓历史与开仓限制

程序启动、手动刷新、Cron 抓取后的开仓都经过同一个 `createTrailingOrders`。存在待创建订单时先同步成交历史；每笔实际 POST 前再次同步并查库。Gate 每分钟持仓更新也会同步成交历史。接口或数据库失败时不继续新开仓。

使用 Gate `/api/v4/futures/usdt/my_trades_timerange`，每轮固定查询最近 7 天并分页到空页。同步水位只记录成功进度，不过滤水位以前迟到可见的成交。独立 position_entry_seen 保存七天内的成交身份，展示历史裁剪后仍不会重复插回旧事件。记录使用交易所 `create_time` 转 UTC 毫秒，`trade_id` 使用文本避免大整数精度丢失。仅处理真实成交，不以提交追踪单成功或仓位大小变化认定入仓。七天以外的迟到成交不属于本轮回看范围；完整分页增加读取量，限流和实际可见延迟仍需受控验收。

`size`、`close_size` 兼容旧接口的 JSON 安全整数（绝对值不超过 9007199254740991）和新接口的十进制字符串；字符串数量通过精确十进制比较，不经浮点转换。数字小数、超出安全范围的数字、缺失或错误类型、零成交数量、方向冲突都拒绝并暂停；失败批次不保存历史或推进进度。字段错误会指出 `size`、`close_size` 或 `contract`，不回显原始内容。

按官方 `size`、`close_size` 判断：正数量超过正平仓数量时开多，负数量超过负平仓数量绝对值时开空；`close_size=0` 表示全为开仓。纯平仓及部分平仓不记录；反手仅记录新开的方向。加仓也记一条并重新算 7 天。同一订单分多次实际成交时，每个成交 ID 是一个确认入仓事件；重复轮询同一成交不再新增。未成交的订单不记录，即使仓位在两次轮询之间先开后平，真实成交仍会被记录。

`position_entry_history` 记录实际入仓时间、合约、方向 1/-1 和去重事件 ID。每次写入在同一事务内按实际时间从新到旧仅保留 100 条；时间相同时按事件 ID 稳定排序。`position_entry_sync`、独立去重身份、保证金和历史一起提交；同步不完成时均不改变。

开仓检查以当前时间为准，查询 `[当前时间-7天, 当前时间]`，同合约、同方向存在记录就跳过；恰好 7 天仍限制，超过 7 天不限制。相反方向不影响。100 条与 7 天是独立条件，7 天内被数量上限清理的记录不再限制开仓。原有状态 1/2 参数完全相同的有效订单继续保留；本检查针对新提交的开仓单，不追溯撤销正在执行的订单。

历史同步按 API Key 摘要区分进度；本地历史检查依据当前表实际保留记录。正常运行要求使用一致的系统时间和可读取成交历史的 Gate API 权限。程序内交易流程串行，历史写入继续使用现有 SQLite 事务、跨进程数据库锁和 450 MB 上限；不新增跨进程交易幂等保证。

旧 `managed_close_orders` 表不再创建或使用；为了保留旧库数据，不执行删除旧表的迁移。

接口字段定义见 [Gate 官方期货文档](https://www.gate.com/docs/developers/apiv4/en/futures/)。

## 固定入仓保证金（issue #21）

`position_entry_history.initial_margin` 是可空的十进制文本。同步到新入仓、加仓或反手开仓成交后，再读取 Gate 当前持仓，把每个合约方向最新成交对应的持仓整体保证金保存下来。提交追踪开仓单成功不算成交，不更新保证金。分页或保证金接口失败时，历史和进度不提交，新开仓暂停。

成交接口不提供每笔成交时的 initial_margin，因此程序保存的是确认成交后首次成功观察到的持仓保证金，不伪造历史成交时的值。同一批补抓到多笔成交时，只给每个方向最新一笔填写当前观察值；更早记录保持空值。已在两次轮询之间完全平掉的方向也保持空值，待有可读取的当前持仓时初始化。

升级时自动给旧历史表加列。旧持仓第一次成功读取时保存当前保证金，已有最新历史记录也补齐该列；没有历史时不伪造入仓事件、不重新开始 7 天限制。`position_entry_margin` 按 API Key 摘要、合约和方向保存当前固定值及最新事件，保证历史超过 100 条被清理后固定值仍保留。它和成交历史在同一事务内更新；新成交没有当前持仓时将固定值置空，下一次读取该方向持仓时初始化。

重复成交不会覆盖保证金，重启不重新取值。行情变化、纯平仓或部分平仓、修改杠杆和单独增减保证金不更新固定值。新的真实入仓或加仓只更新对应账户、合约、方向。`position.initial_margin` 和平仓计算统一使用固定值；实时保证金只用于新成交或旧持仓的初始化。SQLite 迁移只加列和表，旧数据保留。
